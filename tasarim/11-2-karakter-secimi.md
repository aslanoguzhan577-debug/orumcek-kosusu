## Real Three.js scene recipe (production, not placeholder art)

Use the existing renderer/canvas, scene, player and eleven prebuilt models from `main.js:70–78`; `game.setSkin` already swaps roots and updates `iron.normalModel`. Do not load, clone or rebuild models on selection. UI calls a new `game.setMenuView('menu'|'skin'|null, rect)` owned in main.js; `showScreen` calls it only on screen changes, then on resize. Null on help/market may retain last menu shot but freeze spin; null on run must restore chase. Avoid separate cameras and additional rAF.

1. Enter skin only from menu: save player.root position/quaternion/scale and each modified model yaw; set root `(0,0,0)`, rotation identity, scale unchanged; `player.model.setState('idle')`. Disable any existing menu auto-camera while stage owns camera. Hide chaser root, obstacles' render root/instances and all pickups, extra Iron Man helper only for menu previews; retain previous visibility to restore. Hide world only if its rails intrude on the pedestal safe window; default **keep world + skyline**, stationary at distance0. Do not reset mission/shop data or alter gameplay distance. Scene background sky remains.
2. Compute stage hero window rect from DOM `getBoundingClientRect()` (above). Use renderer scissor+viewport to that rect, after full-frame sky clear; camera aspect=rect.width/rect.height, FOV **35°**, near .1/far existing. Bounding Box3 of **selected visible model root only**, including costume ears/cape; `h=box.max.y-box.min.y`, `w=2*Math.hypot(xExtent/2,zExtent/2)` so every yaw angle fits. Target `(0,box.center.y,0)`; `distance=max(h/(2*tan(17.5°)),w/(2*tan(17.5°)*aspect))*1.18`. Camera position target+`(0,h*.06,distance)` lookAt target. Use box floor/center from world coordinates after root placement; traverse visible meshes only (skip hidden subtrees), not Box3 over the entire player containing hidden skins. Cache local bounds during warm-up, transform bounds on selection. Convert DOM rect to GL bottom-left CSS-pixel viewport/scissor `(rect.left, innerHeight-rect.bottom, rect.width, rect.height)`; renderer applies pixel ratio, do not multiply twice. Spin selected model.root around Y at **0.22 rad/s**, with a fixed front bias `-0.18rad`, stopped under reduced motion. Existing model idle update continues, normal player root bank placement must be skipped while menu view owns root.
3. Halftone starburst is a DOM sibling behind the canvas? Full canvas would cover it. Implement **DOM overlay above canvas but behind name/UI**, centered on hero window, pointer-events:none, radial/repeating-conic gradient, opacity .25, mix-blend-mode:multiply, disc diameter `min(rect.width*1.05,rect.height*.95)`; preserve transparent gaps so real model stays visible. No procedural texture per tap. CSS burst in prototype is this overlay.
4. Swap: existing setSkin first, remeasure bounding box, token pop; show **DOM** comic puff over hero window for **240ms**, 6 cream circles (diameters44/32/38/26/34/30) positioned in a 120×80 cluster, border2 ink, scale(.4→1.2), opacity1→0 with ease-out; `POF!` 24 Bangers at center. Precreate once. No flash over lanes, no material allocation. Reduced motion: instant swap, no puff. Cancel previous puff when taps are rapid; only latest model visible.
5. Return menu: restore model yaw and root transform first; use menu view (same framing algorithm), hero window **the actual clear menu band DOM rect (234px high at360×740;299px at490×805)** portrait. Name and UI menu card leave that window clear; landscape menu hero window is left column x12..312,y70..H-24. Stage menu spin .08rad/s or none under reduce. Change view over **180ms ease-out** (position/look interpolation), not a black screen. On run/intro: restore visibility, quaternion/scale/root position and original FOV; renderer scissor off/full viewport, call `cameraRig.resize(runWidth,runHeight)` and `cameraRig.snap(player)` before intro; intro owns camera until end. Run later uses reserved HUD viewport. Never leave `setShot` active into a chase. Pause/resume does not enter menu preview; help/market return keeps selected model and menu state. SetSkin while paused is unsupported; keep selection accessible from menu only.

Camera distances are computed starting values, **not observed**. Phone acceptance must check Hulk/Kitty ears, Batman cape, all 11 silhouettes, landscape hero size and transitions before director approval.
